# 원기랜드 HTML 수정 및 검증

## 파일과 분석
- 원본: original.backup.html (수정 전에 복사)
- 원본 SHA-256: abe8cbc43cb426c3ca2d9bbf2cac18024d0ad73dfb3bfc713beff8668fca2ab7
- 수정본: wonkiland_fixed.html
- HTML 전체의 마크업, 32개 원본 스크립트, 내장 이미지·음악 데이터, 메뉴 생성 및 이벤트 연결을 조사했습니다.
- 원본에는 음악 메뉴가 한 개 있으며 게임을 열 때만 표시됩니다. 비공개 테스트 화면/메뉴는 없습니다. 사용자 확인에 따라 기존 드래곤볼 수학게임 선택 화면을 연결했습니다.

## 변경 사항
1. 기존 음악 메뉴 레이어를 메인 화면에서도 표시합니다.
2. 음악 메뉴 버튼을 이동하여 비공개 테스트 버튼과 함께 오른쪽 하단 메뉴 영역에 한 개씩 배치합니다. 기존 버튼을 복제하지 않습니다.
3. 비공개 테스트 버튼은 비밀번호 입력 모달을 열며 비밀번호는 5283입니다.
4. form submit 이벤트에서 preventDefault()로 기본 제출을 막습니다. location 변경, reload, 외부 페이지 전환은 사용하지 않습니다.
5. 비밀번호가 맞으면 기존 wonkiStartDbzGame()을 호출해 현재 화면 위에 기존 게임 모달을 표시합니다. 게임 닫기 동작은 기존 동작을 유지하며 메인 화면 DOM을 다시 만들지 않습니다.
6. 취소와 Escape로 비밀번호 모달을 닫을 수 있습니다. 비밀번호는 열기/닫기 시 지우며 정상 진입한 게임을 닫으면 메뉴 버튼으로 초점을 돌려줍니다.
7. 기존 음악 재생/일시정지 및 음량 로직을 유지하고 버튼 문구를 동작에 맞게 정리했습니다.

## 보존 확인
원본 텍스트와 수정본을 비교해 기존 내용 중 음악 메뉴 표시 조건 1개, 음악 버튼 문구 2개만 바뀌었음을 확인했습니다. 그 외에는 하단 메뉴·비밀번호 모달 스타일과 컨트롤러를 추가했습니다.
회원관리, Google Apps Script 동기화, 방명록, 가구 배치, 게임 규칙·저장·캐릭터 이미지 및 모든 기존 내장 이미지/음악 데이터는 원본 그대로입니다.

## 검증 결과
Chromium/Playwright에서 데스크톱 1280×900과 모바일 390×844 환경으로 검사했습니다.
- 메뉴가 각각 한 개씩 표시됨
- 비밀번호 오입력 시 모달 유지 및 게임 미실행
- 5283 입력 후 Enter로 기존 게임 모달 표시
- 3회 연속 열기/닫기 성공
- 취소 및 Escape로 비밀번호 창 닫기
- 전체 과정에서 최초 로드 외 추가 페이지 이동/새로고침 없음
- 모달을 닫은 뒤 메인 화면 HTML이 이전과 동일
- 캐릭터 선택 화면의 기존 이미지 표시
- 음악 실제 재생 상태, 일시정지, 음량 슬라이더와 +/− 조절 확인
- 수정 대상의 음악·비공개 버튼 및 폼 이벤트가 각각 한 번만 연결됨
- 원본 32개 및 수정본 33개 스크립트 JavaScript 구문 검사 통과
- 수정으로 추가된 JavaScript 실행 오류 없음

## 원본에서 발견한 기존 문제 및 검증 범위
원본과 수정본 모두 wonki-multi-course-script에서 Cannot read properties of null (reading 'cloneNode') 오류가 발생합니다. courseSelectTemplate.content.firstElementChild가 null인 상태에서 호출되는 기존 회원 수강과목 코드의 오류입니다. 회원관리 변경 금지 요청에 따라 이 코드는 수정하지 않았습니다.
기존 mathConfirm 버튼은 여러 스크립트의 캡처 단계 이벤트가 연결되어 있으며 그대로 보존했습니다. 새 비공개 진입은 mathConfirm 클릭을 만들지 않고 기존 게임 열기 함수만 한 번 호출합니다.
외부 네트워크 호출은 브라우저 검사 중 차단했으며 실제 회원 데이터나 Google Apps Script 서버에 쓰기 요청은 보내지 않았습니다. 따라서 원격 동기화의 실제 성공 여부나 모든 게임 진행 규칙을 새로 검증했다는 의미는 아닙니다. 관련 코드와 데이터의 보존을 텍스트 비교로 확인했습니다.

참고: 단일 HTML 안의 비밀번호는 소스에서 확인 가능하므로 서버 인증과 같은 접근 통제는 제공하지 않습니다.
