# 원기랜드 수정본 v2

## 이번 수정
- 화면 오른쪽 아래 고정을 제거했습니다. 두 버튼을 메인 지도 하단의 기존 방문자·신규회원·전체 동기화 메뉴 영역에 포함시켰습니다. 작은 화면에서도 메뉴가 잘리지 않도록 같은 영역 안의 다음 줄에 배치했습니다.
- 게임 모달에서는 같은 두 버튼을 복제하지 않고 게임 화면 하단 가운데로 이동합니다. 게임을 닫으면 기존 메인 하단 메뉴로 돌아옵니다.
- 비공개 테스트 버튼은 비밀번호 입력 오버레이를 엽니다. 브라우저 기본 dialog.showModal() 의존성을 제거하고 명시적인 표시/숨김과 클릭·submit 이벤트로 처리합니다.
- 비밀번호는 5283입니다. 틀리면 오류를 표시하고, 맞으면 기존 드래곤볼 게임 선택 화면을 현재 페이지 위에 엽니다.
- 기본 form 제출과 페이지 이동·새로고침을 차단했습니다. 취소, Escape, 배경 클릭으로 비밀번호 창을 닫을 수 있습니다.
- 음악 재생·일시정지·음량 조절을 유지했습니다. 음악 설정 창은 버튼 위에 표시되고 화면 너비에 맞게 위치합니다.
- 관련 메뉴 이벤트는 한 컨트롤러에서 각 한 번만 연결합니다.

## 보존 확인
최초 원본에서 음악 메뉴 UI 컨트롤러 1개와 재생 버튼 문구 1개만 변경하고 하단 메뉴 컨트롤러·마크업·스타일을 추가했습니다. 회원관리, Google Apps Script 동기화, 방명록, 가구 배치, 기존 게임 규칙·캐릭터 이미지·문제·내장 오디오는 원본 텍스트 그대로 보존했습니다.

## 실제 브라우저 검사
Chromium 데스크톱 1280×900, 모바일 390×844에서 검사했습니다.
- 두 버튼이 실제 메인 하단 메뉴 내부에 있으며 같은 줄에 배치됨을 DOM 및 좌표로 확인했습니다.
- 데스크톱 마우스 클릭과 모바일 터치로 비밀번호 창이 열렸습니다.
- 오입력 시 게임이 열리지 않았고 5283 및 Enter 입력 후 게임이 열렸습니다.
- 열기·닫기를 3회 반복했고 취소·Escape를 검사했습니다.
- 게임 안에서 같은 음악 버튼이 동작하고 닫으면 메인 메뉴로 복귀했습니다.
- 음악 실제 재생·일시정지·슬라이더 및 +/- 음량을 확인했습니다.
- 첫 로드 외 페이지 이동은 없었습니다. 닫은 뒤 메인 화면 HTML은 동일했습니다.
- 검사 대상 버튼 및 폼 이벤트는 각각 한 번만 연결되어 있었습니다.
- 원본 및 v2의 32개 스크립트 구문 검사를 통과했고 수정으로 추가된 실행 오류는 없었습니다.

## 기존 오류와 배포 확인 한계
원본에서도 회원 수강과목 코드 wonki-multi-course-script의 cloneNode 오류가 발생합니다. 회원관리 변경 금지 요청에 따라 해당 코드는 수정하지 않았습니다.
제공된 Neocities 주소는 작업 환경에서 HTTP 403 응답을 받아 실제 배포본과 로컬 파일을 비교하지 못했습니다. 따라서 기존 배포 페이지의 버튼 무반응 원인은 확정하지 못했습니다. v2는 파일 자체를 로컬 HTTP로 제공한 Chromium에서 위 동작을 확인한 결과입니다. 원격 동기화 서버에 쓰기 요청은 보내지 않았습니다.
